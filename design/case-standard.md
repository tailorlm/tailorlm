# 案例标准

一个案例的作用是让潜在客户相信“你能在我的场景里做到”，不是展示你跑过训练。

## 必须有的

- **基线**：训练前原模型在同一测试集上的表现。
- **固定测试集**：不参与训练，评分规则可复现。
- **前后对比**：同一指标、同一测试集、同一推理参数。
- **回归**：通用能力没有明显退化。
- **失败案例**：至少 2 个，说明边界。
- **成本**：GPU 小时、云成本、失败重跑。
- **可复现**：配置、数据 manifest、随机种子、版本。
- **授权**：客户书面同意；或完全使用公开数据自建。

## 不算案例的

- 只有 loss 曲线；
- 只挑几个好看例子；
- 没有测试集，靠“感觉”；
- 没有基线；
- 没有失败案例；
- 客户数据未脱敏；
- 不可复现的“内部实验”。

## 最小交付

```text
case.md              案例正文
config/              训练配置
eval/                评测集和评分脚本（可公开部分）
artifacts/           adapter/模型指针、推理示例
```

## 写作

- 先给结论，再给证据。
- 数字优先，形容词靠后。
- 失败案例和结果一样重要。
- 不确定的地方明确写“不确定”。
